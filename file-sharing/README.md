# Файлообменник без регистрации

Загружаете файл(ы) — получаете ссылку. По ссылке получатель видит удобную
страницу: фото и видео открываются превью прямо в браузере, текстовые файлы
можно посмотреть без скачивания, а всё остальное — скачивается в один клик
(или всё сразу архивом ZIP). Без учётных записей, паролей и БД.

## Почему один файл

Это переписанная версия. Раньше приложение состояло из отдельных
`.php`/`.js`/`.css`/`.htaccess` файлов в подпапках — и именно это оказалось
проблемой на реальном хостинге: при заливке по FTP легко случайно вложить
папку на уровень глубже, `.htaccess` не работает, если у провайдера выключен
`AllowOverride` (частая история на дешёвых тарифах), а лишние файлы — это
лишние места, где что-то может потеряться при переносе.

Теперь всё приложение — **один файл `index.php`**. HTML, CSS и JS
сгенерированы и встроены прямо в него, никаких подпапок с ассетами и
никакого `.htaccess`. Нужна только сама папка `data/` рядом с `index.php`
для хранения загруженных файлов и метаданных (JSON).

## Установка

1. Загрузите на хостинг **всего два объекта**: файл `index.php` и папку
   `data/` (пустую, с правами на запись) — они должны лежать в одном месте.
   Если открываете по адресу `https://ваш-домен/f/`, то `index.php` должен
   лежать именно в папке `f`, а не на уровень глубже.
2. Проверьте права на папку `data/`: `755`, а если хостинг капризничает —
   `777`.
3. Откройте `index.php` в браузере (или просто адрес папки — большинство
   хостингов сами подставляют `index.php`).
4. Если что-то не работает — откройте `index.php?diag=1`: страница покажет
   версию PHP, реальные лимиты загрузки (`upload_max_filesize`,
   `post_max_size`), доступность расширений `fileinfo`/`zip` и то, доступна
   ли папка `data/` для записи. Это устраняет угадывание — сразу видно,
   какое именно ограничение выставил провайдер.

## Ограничения дешёвого хостинга и как приложение их обходит

- **Маленький `upload_max_filesize`/`post_max_size` (частый лимит 2–8 МБ)**
  — эти значения задаёт провайдер в `php.ini`, из кода их не поднять.
  Страница загрузки честно показывает текущий лимит и ссылку на
  `?diag=1`. Если нужен файл побольше — единственный способ поднять лимит
  без доступа к `php.ini` — попросить это у поддержки хостинга или (если
  доступен PHP как FastCGI/PHP-FPM) добавить `.user.ini` в ту же папку:
  ```
  upload_max_filesize = 512M
  post_max_size = 550M
  ```
  Это не входит в поставку по умолчанию — не все хостинги разрешают
  `.user.ini`, и если он не поддерживается, файл просто игнорируется без
  ошибки.
- **Нет доступа к cron** — истёкшие ссылки не ждут отдельного
  cron-задания: при случайном заходе на любую страницу с вероятностью
  ~1/20 запускается фоновая проверка и чистка истёкших ссылок.
- **Отключено расширение `zip`** — кнопка «Скачать всё (ZIP)»
  автоматически не показывается, если `class_exists('ZipArchive')` вернул
  `false`; остальной функционал продолжает работать, файлы скачиваются по
  отдельности.
- **Отключено расширение `fileinfo`** — определение типа файла падает на
  резервный вариант через `mime_content_type()`, а если и его нет — на
  таблицу соответствий по расширению файла.
- **Старая версия PHP** — код совместим с PHP 7.2+, без синтаксиса,
  доступного только в PHP 8 (`match`, `str_starts_with` и т.п. не
  используются напрямую).
- **`.htaccess` не работает (`AllowOverride None`)** — приложению он не
  нужен вообще. Прямой URL на файл внутри `data/` подобрать нельзя без
  знания случайного 128-битного идентификатора ссылки, а листинг папок по
  умолчанию отключён почти на всех хостингах.

## Безопасность

- Ссылки используют непредсказуемый 128-битный идентификатор
  (`random_bytes`) — без него скачать файлы нельзя.
- MIME-тип определяется на сервере, а не по расширению/заголовку от
  клиента (кроме резервного случая при полностью урезанном PHP).
- SVG и HTML никогда не отдаются как `inline` (могут содержать скрипты) —
  только как вложение для скачивания; остальные inline-ответы отдаются с
  жёстким `Content-Security-Policy: default-src 'none'; sandbox`.
- Текстовый предпросмотр вставляется на страницу через `textContent`, а не
  `innerHTML` — содержимое файла не может быть интерпретировано как
  HTML/JS, даже если внутри есть теги `<script>`.
- Путь к файлу на диске всегда проверяется через `realpath()` и сверяется
  с папкой конкретной ссылки — обхода каталога (`../`) нет.
