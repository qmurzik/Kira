# Кира — AI-ассистент QMODS в Telegram

Кира — виртуальный ассистент проекта QMODS: общается с пользователями в личных
сообщениях и в теме форума Telegram-группы, помогает с модами, аккаунтом,
настройками и вопросами по сайту/приложению. Полностью работает на бесплатном
тарифе Cloudflare — без VPS и без платных API по умолчанию.

## Архитектура

```
Telegram (webhook)
   │
   ▼
Cloudflare Worker (src/index.ts)
   │  проверка секрета вебхука → ответ 200 сразу → ctx.waitUntil(обработка)
   ▼
src/telegram/router.ts
   ├─ команды: /start /help /profile /settings /clear_memory
   ├─ middleware/topicFilter — фильтр по теме форума / упоминанию
   ├─ middleware/rateLimit  — лимит ответов на пользователя в час (KV)
   └─ handlers/message.ts  — основной AI-диалог
        │
        ├─ memory/manager.ts
        │    ├─ KV  (KIRA_KV)  — короткая история диалога, TTL
        │    └─ D1  (DB)       — профиль пользователя, настройки чата
        │
        └─ ai/index.ts — фабрика провайдера (Cloudflare Workers AI / Groq / OpenRouter)
```

Ответ на webhook уходит мгновенно (Telegram требует быстрый 200 OK), а сама
генерация ответа, задержка и запись в память выполняются в фоне через
`ctx.waitUntil`.

## Почему такая модель ИИ

Приоритет отдан полностью бесплатным вариантам без регистрации во внешних
сервисах:

1. **Cloudflare Workers AI** (`AI_PROVIDER=cloudflare`, по умолчанию) —
   модель `@cf/meta/llama-3.3-70b-instruct-fp8-fast` через биндинг `env.AI`:
   квантованная fp8-версия Llama 3.3 70B, специально оптимизированная под
   скорость, без reasoning-надстройки (в отличие от многих новых моделей
   каталога вроде `glm-4.7-flash`, которые перед ответом тратят время на
   скрытые "раздумья" — это ощутимо замедляет чат-бота). Хорошо говорит
   по-русски, бесплатна в рамках дневного лимита нейронов Workers Free plan,
   ключей не требует. Модели Workers AI периодически устаревают — если
   `AI_MODEL` вернёт ошибку `5028 deprecated`, смотрите актуальный список на
   [странице каталога](https://developers.cloudflare.com/workers-ai/models/)
   и меняйте значение в `wrangler.toml`, без правок кода.
2. **Groq** (`AI_PROVIDER=groq`) — запасной вариант с щедрым бесплатным
   тарифом (`llama-3.1-8b-instant`), нужен `GROQ_API_KEY`.
3. **OpenRouter** (`AI_PROVIDER=openrouter`) — модели с суффиксом `:free`,
   нужен `OPENROUTER_API_KEY`.

Провайдер и модель переключаются только через `wrangler.toml` (`AI_PROVIDER`,
`AI_MODEL`), без изменений в коде — интерфейс `AIProvider` (`src/ai/types.ts`)
одинаков для всех.

## Структура проекта

```
/src
  /telegram      Telegram-клиент, роутер, команды, middleware, обработчики
  /ai            Провайдеры ИИ, сборка промпта, системный промпт-персонаж
  /database      Работа с D1 (пользователи, настройки чата, лог ошибок)
  /memory        Короткая память (KV) + долговременная (D1), менеджер
  /config        Типы env, персонаж Киры, константы
migrations/      SQL-миграции D1
scripts/         Автоматизация деплоя и настройки webhook
wrangler.toml    Конфигурация Worker, биндингов и переменных
```

## Персонаж

Кира — аниме-девушка с короткими чёрными волосами с фиолетовыми кончиками,
фиолетовыми глазами, серебряными заколками-крестиками, в тёмной одежде с
фиолетовыми элементами (эстетика cyber/goth/anime, дружелюбный образ).
Характер: дружелюбная, немного милая, умная, спокойная, иногда шутит, не
official-formal. Описание и системный промпт — в `src/config/character.ts`,
единый источник правды для `/start`, `/help` и будущих интерфейсов
(мини-приложение, сайт).

## Память

- **Короткая (KV, `KIRA_KV`)** — последние N сообщений диалога на пользователя
  в чате (`SHORT_TERM_LIMIT`, по умолчанию 12), автоматически стирается по TTL
  (`SHORT_TERM_TTL_SECONDS`, по умолчанию 7 дней).
- **Долговременная (D1, `DB`)** — имя, username, счётчик сообщений,
  предпочтения (`preferences_json`) в таблице `users`.
- **Приватность**: `/clear_memory` удаляет и KV-историю, и запись профиля в D1
  полностью. Ежедневный cron (`scheduled`) чистит старый лог ошибок.

## Работа в группах и темы форума

Кира не отвечает на каждое сообщение в группе:

- отвечает **всегда**, если сообщение находится в закреплённой за ней теме
  форума;
- тема определяется **автоматически**, если при создании темы её название
  содержит `KIRA_TOPIC_NAME` (по умолчанию "Кира AI", например "💜 Кира AI");
  либо вручную — команда `/settings set_topic`, отправленная администратором
  внутри нужной темы;
- вне этой темы отвечает, только если её позвали: `@username_бота`, ответ на
  её сообщение, либо обращение по имени ("Кира, ..."). Это поведение можно
  выключить (`STRICT_TOPIC_ONLY=true` в `wrangler.toml`) — тогда вне
  назначенной темы Кира полностью молчит;
- в личных сообщениях отвечает всегда.
- есть лимит ответов на пользователя в час (`RATE_LIMIT_PER_HOUR`) и
  небольшая задержка перед ответом (`RESPONSE_DELAY_MS`), чтобы не выглядеть
  спам-ботом.

## Развёртывание

Проект подключён к **Cloudflare Workers Builds** — деплой воркера `kira`
происходит автоматически при пуше в эту ветку (Cloudflare сам выполняет
`npx wrangler deploy`). Ресурсы уже созданы и прописаны в `wrangler.toml`:

- Worker: `kira`
- D1: `qmods-telegram-bot` (таблицы `users`, `chat_settings`, `error_log`
  из `migrations/0001_init.sql` уже применены)
- KV: `KIRA_KV`
- R2 пока не подключён — на аккаунте не включён R2 (Cloudflare Dashboard →
  R2 → Enable), биндинг в `wrangler.toml` закомментирован. Он и не
  используется в коде сейчас, понадобится только для будущей базы знаний.

Автодеплой поднимает **только сам Worker** — секреты и webhook он не
настраивает, это разовые ручные шаги:

### 1. Секреты (Cloudflare Dashboard → Workers → kira → Settings →
Variables and Secrets, либо `wrangler secret put`, если есть локальный доступ
к аккаунту)

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN        # токен от @BotFather
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET   # любая длинная случайная строка
# опционально, только если меняете AI_PROVIDER:
npx wrangler secret put GROQ_API_KEY
npx wrangler secret put OPENROUTER_API_KEY
```

### 2. Регистрация webhook Telegram (один раз, после того как секреты заданы
и первый деплой прошёл)

```bash
cp .env.example .env   # впишите TELEGRAM_BOT_TOKEN, TELEGRAM_WEBHOOK_SECRET,
                        # WORKER_URL=https://kira.<ваш-поддомен>.workers.dev
npm run setup:webhook
```

### Локальный CLI-путь (если нужен деплой не через git, а вручную)

```bash
npm install
npx wrangler login
npm run db:migrate:remote   # если меняли миграции — применит новые к qmods-telegram-bot
npm run deploy
npm run setup:webhook
```

### 4. Telegram-группа

1. Включите Topics (Темы) в настройках группы.
2. Создайте тему с названием, содержащим "Кира AI" (например "💜 Кира AI") —
   Кира сама её запомнит при первом сообщении в ней.
3. Добавьте бота в группу с правом читать сообщения (Group Privacy Mode можно
   оставить включённым, если Кира должна реагировать только на команды и
   упоминания вне своей темы; для полноценной работы внутри её темы
   отключите Privacy Mode у @BotFather: `/setprivacy` → `Disable`).

## Интеграция с qmods.ru (личный кабинет)

Кира умеет отвечать на вопросы про подписку ("сколько дней осталось",
"какой у меня тариф") через уже существующий self-service API личного
кабинета — `mod/api/client_api.php` на самом сайте. Отдельный секрет
для этого не нужен: Кира действует от имени конкретного привязанного
пользователя, а не как административный клиент.

- `/link логин пароль` (только в личных сообщениях) — Кира логинится в
  `client_api.php/login`, получает `session_token` (Bearer, живёт 30 дней —
  срок задаёт сам сайт) и сохраняет только его в D1 (`qmods_links`).
  **Пароль нигде не сохраняется** — используется один раз для получения
  токена и сразу забывается.
- При каждом сообщении привязанного пользователя Кира подтягивает статус
  подписки (`client_api.php/subscription`) с кэшем в KV на 10 минут, чтобы
  не дёргать сайт на каждое сообщение, и передаёт точные цифры модели как
  системный контекст — в промпте прямо указано не выдумывать данные о
  подписке, а брать только из этого контекста.
- `/unlink` — отвязать аккаунт (плюс серверный logout сессии).
- Если токен истёк (сайт вернул 401) — Кира сама тихо отвязывает аккаунт и
  подскажет пользователю привязать заново.

Ограничение самого сайта: `client_api.php/login` отказывает в логине, если
подписка сейчас не активна (так у него сделано для Android-приложения) —
в этом случае Кира прямо покажет сообщение сайта с причиной.

## ⚠️ Обнаруженная проблема безопасности в исходниках сайта

В `mod/includes/telegram.php` в открытом виде захардкожен токен другого
Telegram-бота (используется для уведомлений админу о платежах/регистрациях).
Раз он лежит в коде — считайте его скомпрометированным: перевыпустите через
@BotFather (`/token` или `/revoke`) и вынесите в переменную окружения
вместо константы в файле. К самой Кире это не относится, но стоит поправить.

### Локальная разработка

```bash
npm run db:migrate:local
npm run dev
```

Для локального теста используйте `wrangler dev --remote` или туннель
(например `cloudflared tunnel`) и укажите его URL в `WORKER_URL`.

## Безопасность

- Webhook защищён секретным путём **и** заголовком
  `X-Telegram-Bot-Api-Secret-Token` (сверяется в `src/index.ts`).
- Токен бота и ключи AI-провайдеров хранятся только как Worker Secrets, не
  попадают в код и `.git`.
- Rate limiting на пользователя (KV) защищает от спама и от исчерпания
  бесплатного лимита нейронов.
- Все ошибки перехватываются, логируются в D1 (`error_log`) и в консоль
  воркера; пользователь получает нейтральное сообщение об ошибке, без
  деталей реализации.
